# 개요

DBMS는 구체적으로 무슨 일을 하고, 누가 어떤 방법으로 DBMS를 쓰는 걸까?  
이번 글에서는 데이터베이스의 특징, DBMS의 기능과 장단점, 데이터 언어와 사용자에 대해 정리해보려 한다.

---

# 데이터베이스의 특징

### 1. 실시간 접근성 (Real-time accessibility)
- 사용자의 요구에 즉각적으로 응답(Response)해야 한다.

### 2. 계속적인 변화 (Continuous evolution)
- 삽입, 삭제, 갱신이 수시로 일어난다.
- 지난 글 표현으로 말하면 스키마는 거의 그대로고, 인스턴스가 계속 바뀌는 것이다.

### 3. 동시 공용 (Concurrent sharing)
- 여러 사용자가 동시에 자기가 원하는 데이터에 접근할 수 있다.

### 4. 내용에 의한 참조 (Content reference)
- 물리적 주소가 아니라 데이터에 대한 **조건**으로 원하는 결과를 찾는다.
- "몇 번째 레코드"가 아니라 "직업이 Analyst인 사람"으로 찾는 식이다.

```sql
SELECT Name FROM Employee WHERE Job = 'Analyst';
```

나는 배열을 인덱스로 접근하는 것과 값으로 검색하는 것의 차이로 생각하니까 이해가 쉬웠다.

# DBMS의 필수 기능과 장단점

### 1. 필수 기능
- **정의 기능**: 저장될 데이터의 논리적 구조와 물리적 구조를 정의한다.
- **조작 기능**: 저장된 데이터에 대한 검색, 삽입, 수정, 삭제 등 접근을 지원한다.
- **제어 기능**: 무결성 유지, 보안, 회복, 공유 등 데이터의 정확성과 보안을 유지한다.

데이터를 만들고(정의), 쓰고(조작), 지키는(제어) 기능이라고 보면 된다.

### 2. 장단점

| 장점 | 단점 |
|---|---|
| 데이터 중복 최소화, 공용성 증대 | 운영비 증대 |
| 데이터의 일관성, 무결성 유지 | 자료 처리의 복잡화 |
| 데이터 보안 보장 | 시스템 성능에 따라 DBMS 성능이 좌우됨 |
| 범기관적 표준화 가능 | |
| 응용 프로그램 개발이 쉬워짐 | |

- 장점은 대부분 파일 중심 시스템의 종속성, 중복성 문제를 해결한 결과이다.
- 단점은 DBMS라는 소프트웨어 층이 하나 더 생기면서 따라오는 비용이다.

# 데이터베이스 시스템의 구조

### 1. 용어 정리
- DB: 공용을 목적으로 통합해서 저장한 데이터의 집합
- DBMS: DB를 관리하는 소프트웨어 시스템
- DBS(DataBase System): 데이터를 DB로 저장, 관리해서 필요한 정보를 만드는 컴퓨터 중심의 시스템
  - DB와 DBMS를 모두 포함하는 가장 큰 개념이다.

### 2. 구조
```text
                        +--- 관리 도구 --> DBA
[Database] <--> [DBMS] -+--- API --------> 응용프로그램
                        +--- SQL --------> 일반 사용자
```
- 누구든 DB에 직접 접근하지 않고 DBMS를 거친다.
- 사용자 종류에 따라 DBMS와 소통하는 수단이 다르다.

+) DB Machine: 대용량 데이터를 빠르게 처리하기 위해 따로 두는 후위(backend) 컴퓨터

# 데이터 언어와 사용자

### 1. 데이터 언어
사용자와 데이터베이스 시스템 사이의 통신 수단이다.
- **DDL (Data Definition Language)**
  - 스키마를 정의, 수정한다. 객체 간의 관계와 제약도 함께 표현한다.
- **DML (Data Manipulation Language)**
  - 데이터의 삽입/삭제/갱신 등 연산을 수행한다.
- **DCL (Data Control Language)**
  - 무결성, 보안, 회복 등에 대한 작업을 한다. 주로 DBA가 쓴다.

이름을 보면 앞의 필수 기능 3가지와 정확히 짝이 맞는다.

| DBMS 기능 | 데이터 언어 | SQL 예시 |
|---|---|---|
| 정의 기능 | DDL | `CREATE`, `ALTER`, `DROP` |
| 조작 기능 | DML | `SELECT`, `INSERT`, `UPDATE`, `DELETE` |
| 제어 기능 | DCL | `GRANT`, `REVOKE` |

### 2. 사용자
- **일반 사용자**: 질의어로 간단한 검색, 삽입, 삭제, 갱신을 하는 사람
- **응용 프로그래머**: 여러 언어와 DML을 이용해 DB에 접근하는 사람
- **DBA (DataBase Administrator)**: DB 관리에 대한 모든 책임을 지는 사람

### 3. DBA가 하는 일
- 설계와 운영: 스키마 정의, 저장 구조와 접근 방법 설정, 보안·권한 정책, 백업·회복 절차 수립 등
- 행정 및 불평 해결: 사용자의 요구를 분석하고 불만을 해소
- 시스템 감시 및 성능 분석: 이용도, 병목 현상, 이용 패턴 등 분석

스키마 정의와 저장 구조 설정까지 DBA 몫이니, 3단계 스키마를 실제로 관리하는 사람이 DBA라고 볼 수 있겠다.
